# 始まりの話（2026-11-24, crux と Claude）

設計は [design-memo.md](design-memo.md) にあります。経緯の全体は Citlalpol の `docs/ja/idea.md`（1〜13）にあります。ここは swallow に
かかわるところだけです。

1. Citlalpol は外への接続を遮断・転送・代役へ曲げる。三つの段階（接続／何を送るか／何を送ったら何が返ってきてほしいか）のうち、
   2・3 は LSP などの領域：受け取ったものに対してプログラムが発火するので、「何を受け取ったときに何が発火したか」はコードを読めるもの
   でなければ決められない。だから access.json の項目として用意して、設計者が書き込めるようにする。
2. サーバーの機能を一部借りればよい（例：TLS の復号）。Citlalpol がローカルのプログラムを起動できれば、Pact より柔軟で結合を薄くできる。
   段階 3 の表を本物に当てて照合するモード（verify）も要る。
3. verify のプログラムは、xipe_totec と embody のように分離する。名前は swallow（vent、embody など、ややマイナーな英単語を意図的に
   選んでいる系譜）。照合だけでなく応答（serve）も swallow に入れ、プロトコルを解釈する場所を swallow だけにする（Claude の提案）。
4. 設計者が何を返すか・何を発火させるかを決めていない場合は、デフォルトで swallow とする（crux）。
